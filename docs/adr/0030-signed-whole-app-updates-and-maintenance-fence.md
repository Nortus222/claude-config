# Whole-app updates keep a durable maintenance fence until agent health succeeds

The app, Rust host, Bun and agent must advance together, while standalone CLI and login-service applies can outlive the window or restart after a crash. Use Tauri's signed artifacts with signed-version binding, HTTPS and increasing stable versions; the JSON channel manifest remains display/routing data, and compatibility comes from the signed bundle. Rust retains verified bytes and a fixed helper holds the app-install and shared apply locks across replacement. A pending journal also blocks shared apply-lock acquisition after the updater dies or the machine reboots, until a matching installed bundle and agent protocol/runtime health succeed under recovery's lock scope. Recovery preserves machine state and backups; it does not automatically roll back app bytes. Ordinary builds have no production updater key; release configuration requires the owner's public key and independently verified Apple distribution prerequisites. This avoids a second manifest-signing format while making executable/version authentication and interrupted maintenance explicit; signing-key custody and future rotation remain owner decisions before distribution.

Runtime metadata fingerprints final shipped Bun, agent and MCP bytes independently. Refresh only Bun's hash after explicit inner signing and before Tauri seals the outer app, then verify both the finished app and authenticated updater archive without rewriting either artifact. Consistency hashes supplement Apple and updater signature checks; they are not an authentication root when both metadata and files are writable.
