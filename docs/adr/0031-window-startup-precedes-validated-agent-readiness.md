# The window opens before validated agent readiness

A healthy agent still leaves every app reopen waiting for a fresh login-shell probe, while reboot startup can also wait on runtime loading and agent health. Tauri setup now creates the native owner and starts one owned worker before returning; the existing checking state can render while commands await explicit readiness. The worker publishes update coordination only after resolving the trusted state root and saved preferences, independently of agent health during ordinary startup; successful interrupted recovery waits for native health before its first update snapshot. It completes machine readiness only after authenticated runtime validation. Other lifecycle operations await completion before taking their existing locks. Closing cancels pending work, fences late publication and joins the worker after the event loop returns, without stopping the persistent agent. This accepts an observable pending period and command gates to keep the window responsive while preserving fresh identity, maintenance fences and genuine operational state; caching the environment or trusting a provisional setup would weaken those contracts.
