# CLI author checkouts must contain the applied setup baseline

Desktop Setup applies verified immutable Git snapshots and can settle state.json's applied baseline without moving the author's checkout. The CLI continues to read that working tree, including author edits, but refuses machine changes when HEAD is behind or diverges from the applied baseline, or when applied-commit or ancestry evidence is unavailable. A checkout containing the baseline is accepted even with dirty or staged edits. A small read of the applied commit precedes store reads that could migrate legacy choices; setup checks the selected checkout before recording it, and the executor checks the original checkout again under its apply lock before starting steps, including when held items use composed paths. This preserves authoring without resetting files or fetching implicitly; CLI and desktop configuration need not match while their source heads differ.
