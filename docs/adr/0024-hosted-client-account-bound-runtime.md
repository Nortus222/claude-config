# Keep hosted metadata, repository consent and machine execution separate

The optional hosted client needs durable server-ordered choices without granting remote metadata permission to execute. `@nortuscc/hosted-client` owns private credentials, strict HTTP decoding, account-scoped caches and an ordered outbox, while sync verifies consent-bound Git tags and records per-item origins. The agent repairs durable projections before jobs, caps source records at the committed offered head, and serializes account, trust and choice changes with person apply through the shared apply lock followed by its job semaphore. Scheduled jobs only try the apply lock, preventing the existing person-apply lock order from deadlocking. Fresh complete inspection supplies metadata reporting; unknown executable bytes and unsupported ownership releases remain waiting. This keeps local-only operation available and preserves local timestamp-based choices while hosted choices follow server arrival order, at the cost of conservative adoption and declining incomplete or oversized summaries.
