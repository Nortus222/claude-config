# Persist singleton CAS and recoverable device expiry

The approved identities `/id` layout gives each identity or device session its own singleton partition, so the Cosmos Store uses that document's ETag for CAS while account/setup batches keep their minimal partition markers. Unbound device sessions use remaining-deadline TTL; bound claims disable TTL until an explicit restartable sweep CAS-fences the session as expired, fences interrupted machine issuance and deletes the session before removing its account reservation. Keeping claims through failed cleanup trades temporary credential retention and caller-owned sweep scheduling for recovery that cannot lose the evidence needed to stop paused writers; asynchronous Cosmos TTL is not a physical deletion deadline, and the permanent opaque account/setup fences remain limited to ADR0025's existing decision.
