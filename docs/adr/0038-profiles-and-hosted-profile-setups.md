# Profiles and hosted profile setups

Repositories declare optional `profiles/<name>.json` documents with inheritance, skill and integration additions or removals, and built-in file replacements or exclusions. Without a `profiles/` directory the root documents form the implicit `default`; an existing empty directory is invalid. Each hosted setup identifies one repository and profile, and a machine follows one profile through Git or a `nortuscc://follow/<setupId>` link. Link inspection exposes the setup's name, repository URL, profile and latest revision to signed-in users who know its ID; Git read access must be proved before subscribing, because metadata visibility grants no content access. Profile switches preview obsolete or stale holds and item overrides, back up their removal and the followed selection through durable runs, then refetch for inspection only. Before subscription, preview inventory comes from fetched Git main because revision metadata is subscriber-only; subsequent incoming review uses verified announced revisions. Jobs and Setup reads recreate their source from the persisted selection without restarting the app, while hosted followers retain the last verified announced revision during outages. The CLI continues to load root documents and refuses repositories containing `profiles/` with `This setup uses profiles; use the desktop app.`, keeping named-profile selection and publication out of the legacy checkout workflow.
