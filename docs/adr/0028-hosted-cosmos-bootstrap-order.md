# Create shared Cosmos storage before enabling its provisioning ceiling

Azure rejects new offerless containers while an account throughput ceiling is enabled, but this service requires three containers sharing one manual 1000 RU/s database. After read-only preflight proves a new account, the delivery helper therefore creates storage with the ceiling temporarily disabled, verifies its shared layout, then restores ceiling 1000 before the dependent application can be created. Bootstrap creates no application, runtime identity, roles or logging resources; the final template omits database/container PUTs. Existing upgrades and rollback require capped, owned storage and never relax its ceiling. The bootstrap flag remains internal, absent from public config and dispatch inputs. Failed bootstrap can retain uncapped or partial storage, so retries fail closed pending separately reviewed owner reconciliation. This accepts a bounded initial provisioning exception to preserve shared throughput; no dedicated offers, automatic adoption or deletion are introduced.
