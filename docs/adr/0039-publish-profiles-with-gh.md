# Publish profiles from the agent clone through gh

Authoring needs a preview that still describes what reaches remote `main`, without changing the configured checkout or coupling Git success to hosted availability. The agent-owned clone is the only write target: it refreshes `main`, replays frozen draft intents rather than applying saved patches, compares the canonical diff with the accepted preview and pushes through `gh` credentials without forcing. Runs bind the base and affected profiles before execution and checkpoint the commit before pushing; recovery checks remote ancestry, including a successful push whose reply was lost. Each commit receives `nortuscc/<full-commit-sha>`, while hosted announcement is separate and retryable: compare resolved items with the previous announced commit, reconcile existing commit/tag/items and sequential-number conflicts, and retain pending profiles after failures. An older unannounced commit cannot follow a newer announced commit. This keeps Git publication useful offline and prevents duplicate or backward announcements without another journal. Upstream discovery uses the installer's pinned `skills` CLI so discovery and installation share one version contract.
